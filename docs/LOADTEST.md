# Навантажувальний тест Tasks API

Сценарій k6 запускає наростання від 0 до N за 3 хвилини, тримає N протягом 5 хвилин і зменшує кількість віртуальних користувачів до 0 за 2 хвилини. Остання незавершена ітерація отримує до 10 секунд на завершення.

Кожна ітерація створює одну задачу, шість разів читає список завершених задач, читає щойно створену та контрольну задачі за ID і отримує профіль власника через `GET /auth/me`. Прапорець `done=true` тримає розмір списку сталим між порівняльними прогонами, хоча кількість нових незавершених задач зростає. Вісім тимчасових акаунтів і контрольні задачі створюються перед початком вимірювання. Прогони слід виконувати на власному тестовому сервісі, оскільки вони створюють записи в БД.

```bash
BASE_URL="$(terraform -chdir=infra output -raw app_url)" VUS=40 CACHE_MODE=off k6 run loadtest/tasks.js
```

`VUS=40` — початковий параметр. Якщо на фазі сталого навантаження ECS не додає завдання або не досягає 3, дочекайся повернення до 1 та підвищи N для наступної спроби. Зафіксуй однакове остаточне N для обох вимірювань кешу. `CACHE_MODE` перевіряє режим, у якому розгорнуто застосунок. Режим на ECS змінюється через `tasks_cache_enabled` і нову активну ревізію task definition.

Для перевірки API двома короткими ітераціями додай `SMOKE=1`. Хмарний тест виконання вимог запускається без цього прапорця. Після кожного тесту у вкладці ECS Service перевір `Running tasks` і `Desired tasks`. Перед наступним тестом обидва значення мають бути 1, функція масштабування за розкладом має бути вимкнена.

`loadtest/results-off.json` і `loadtest/results-on.json` містять статистику лише запитів вимірюваного сценарію. Відсоток помилок дорівнює `error_rate × 100`. Фази реєстрації та підготовки в статистику HTTP сценарію не входять. Показник `checks_pass_rate` також враховує перевірки кодів відповідей та режиму кешування.

| Режим | N | Запити | Помилки, % | p50, мс | p95, мс | p99, мс |
|---|---:|---:|---:|---:|---:|---:|
| Без кешу | — | — | — | — | — | — |
| З кешем | — | — | — | — | — | — |

Результати AWS очікують вимірювання після деплою. Локальний smoke-тест слугує перевіркою сценарію та контракту API.

Під час локальної перевірки проти PostgreSQL обидва короткі прогони виконали по 20 запитів із 0% HTTP-помилок. Ці результати підтверджують роботу сценарію. Числа в таблицю вносяться після повних AWS-прогонів.
