# Асинхронне створення задач через SQS

Terraform створює SQS Standard Queue, DLQ, окремий ECS Fargate worker і політики його масштабування, коли `enable_task_queue=true`. API має дозвіл `sqs:SendMessage`, worker — лише читати й підтверджувати повідомлення з цієї черги. За базового режиму worker має 0 завдань. CloudWatch додає по одному при наявності повідомлень у черзі, з обмеженням 3. Після трьох хвилин із порожньою чергою і без повідомлень в обробці scale-in ставить 0.

`POST /task-jobs` приймає тіло `{"title":"Приклад"}`. Після приймання повідомлення SQS повертає `202 Accepted`, `Location`, `status_url` і підписаний `ticket` на 24 години. Клієнт опитує `GET <status_url>` з тими самими Bearer-даними власника й заголовком `X-Job-Ticket: <ticket>`. Успішне завершення повертає `status: completed` і створену задачу. Поки результату в БД немає, повертається `pending`. Після 5 невдалих спроб повідомлення переноситься в DLQ для перевірки. Клієнтський стан у такому випадку залишається `pending` до кінця дії квитка.

Доставка «щонайменше один раз» означає, що SQS може видати те саме повідомлення повторно. Worker отримує транзакційне блокування для UUID, створює задачу і квитанцію в одній транзакції PostgreSQL, а після коміту видаляє повідомлення з SQS. Якщо worker завершиться між комітом та видаленням, новий worker побачить квитанцію і підтвердить повідомлення без дубліката. Два окремі клієнтські `POST` створюють різні UUID, тому повторна доставка SQS і повторний POST клієнта є окремими випадками.

## Хмарна перевірка

```bash
BASE_URL="$(terraform -chdir=infra output -raw app_url)" VUS=40 CACHE_MODE=off k6 run loadtest/queue.js
```

Використай таке саме N і режим кешу, як у синхронному тесті. Збережи p95 приймання асинхронного запису за весь тест, порівняй p95 ALB на фазі наростання та під час сталого навантаження. На панелі зістав кількість повідомлень SQS, кількість фактичних ECS worker tasks і коливання p95 API. Перевір повернення worker до 0 після спорожнення та збережи знімки. Результати AWS очікують вимірювання.

- [Масштабування ECS за розміром черги SQS](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/service-autoscaling-queue.html)
